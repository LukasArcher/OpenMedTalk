## Translation pipeline
Offline development only: clinician reviews source; GPT and Gemini independently translate same source context, answer options and placeholders, without seeing each other's output. Independent back-translation and semantic checks, compare meaning not literal equality, flag negation, time, anatomy/laterality, medication, quantities, units and ambiguous terms. Record model/vendor/version/date/prompt version/source hash and candidate provenance, no fabricated model consensus. Differences go to human review. Two LLMs may share errors; consensus not proof. Batch resumable import/export JSON, no credentials committed; manual batches supported if no API access. Separate UI strings. No runtime LLM or patient text. 
Review states: draft, ai_generated, ai_consensus, needs_review, community_reviewed, expert_verified, rejected, withdrawn. Per revision and locale. Verified contributors can submit corrections; blind votes, one per distinct verified user, never own translation; no prior count or votes shown until submission. Approval path 1 qualified independent reviewer; path 2 unanimous 3 (low risk) or 5 (moderate risk) independent qualified contributors, no unresolved objections. High risk requires qualified clinical and linguistic expert validation; one reviewer may satisfy both if verified for both. Any objection blocks automatic approval and enters dispute queue; new translation or source revision invalidates prior votes. Approve question + answer bundle in context; audit immutable revisions. Counts are proposed governance thresholds, not evidence. Human maintainer release gate for every patient-facing clinical item; AI-only draft content restricted to visibly labeled demo/preview, not normal clinical build. Low-risk UI may follow separate reviewed policy. Release report per locale, exact revision and coverage; withdrawal blocks future releases and publish urgent correction advice; offline installed builds can't be remotely revoked. 
## Risks and verification
Risk labels provisional.
