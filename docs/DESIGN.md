# Design system
Brand OpenMedTalk; tagline exactly “Clinical communication without barriers”. Approved visual concept: overlapping petrol/mint speech bubbles with white medical cross, charcoal wordmark with Med in petrol. Do not use NordAmbu or Star of Life from older mockups. Reference artwork is stylistic; literal UI text in this document and PRODUCT.md overrides images. Logo concept approved; palette below is a proposed implementation tokenization of the accepted visual direction, not separately signed off.

## Tokens
Light: background #FFFFFF, surface #F6F7F8, subtle #F0F2F3, border #E2E5E7, text #192328, secondary #526169, muted #69767D, brand #08766F, brand pressed #065C56, brand soft #E3F2EF, mint #A9DAD2.
Dark: background #151B1E, surface #20282C, subtle #283236, border #394449, text #F3F6F6, secondary #C1CBCD, muted #A9B6BA, brand #81D0C2, brand soft #233C39; on brand #102522. Validate contrast, do not assume.
Spacing: 4,8,12,16,20,24,32,40,48. Page horizontal inset 20–24; generous 24–32 section gaps. Radius 12–16 for controls, 16–20 for question area. Thin 1px neutral borders, no shadows except native overlays. System sans (SF/Roboto), international script fallbacks (Noto as needed, licensed). Titles 26–32 semibold, body 16–18, patient question 28–36 responsive, patient answers 24–30. Dynamic type, font scaling, RTL and no clipped glyphs. Minimum 48dp touch targets, primary patient choices 96–120dp; no fixed height with long translations. 
Use brand accent sparingly for selection and primary actions. Yes/No equal neutral weight, selected state with text/icon/border; do not imply yes=good or no=bad. White/gray dominates. No gradient, hero banners, redundant badges, badges of counts, explanatory filler, logos on every screen or decorative cards inside cards. Use one consistent outline icon set. Accessible screen reader names, RTL mirroring except anatomy, directionality isolated bilingual labels. Keep question and answer separated by real whitespace. All example strings are draft; no Danish labels on Ukrainian patient screen. 
## Screen inventory
Onboarding welcome/UI language/theme/favorites; settings and about/licensing; language picker/favorites/recent/search; regions/region language list/map/country language choices; category grid/subcategory list/question list/question search/favorite questions; patient boolean, time interval, count, number/date/time, body front/back, radiation, NRS, information; source toggle, unknown/unclear, empty state; log overview and ABCDE/SAMPLER/OPQRST/Other section views, chronological view, edit/delete, copy, QR share, scanner, import preview/conflict, end confirmation. Reuse shared templates not one component per question. Dark mode across all screens.

## UI copy and visual restraint
Implementation accessibility roles: input boundaries use the muted token; decorative row separators retain the border token. Primary pressed controls retain full opacity and use brandPressed (dark: existing mint #A9DAD2), preserving text contrast. Normal/pressed text and input boundary contrasts are checked in `tests/design.test.ts`.
Use the minimum visible text required to operate each screen. Screen title, question/instruction, answer labels, necessary units and action labels are normally sufficient. No subtitles under headings, explanatory text under obvious cards, repetitive hints, promotional slogans inside workflows, “how it works” paragraphs, decorative captions, or filler empty-state text. Do not fill empty space; whitespace is intentional. Examples: “Vælg patientsprog” + search/list, not “Choose the language your patient understands to start a conversation”; “Hjerte” + questions, not a description of cardiac assessment; patient instruction alone + close action, not “No patient response required”. Keep essential safety notices, localized input constraints, meaningful errors, accessibility semantics and clinically necessary information. Move optional explanations to About/Help; no repeated disclaimers on every ordinary screen. Apply to both mobile and portal. The public website may explain the project concisely where useful; no generic marketing filler.
