# Product specification
Status: agreed product direction, implementation and clinical release not yet approved.

OpenMedTalk — Clinical communication without barriers. An international fixed-phrase communication aid for healthcare professionals and patients in acute care (prehospital, ED, urgent wards and related services). Not an interpreter replacement, assessment or journal system. No claims of diagnostic accuracy. Official version free, no subscriptions, advertisements, analytics, tracking, registration or mobile backend.

## Flow
First launch: app/UI language (autodetect with explicit choice), appearance light/dark/system (default system), optional favorite patient languages; editable later. After onboarding, launch directly into patient-language picker. No splash marketing or patient-identification form. Favorites, recent language IDs only (no cases), search across translated names, autonyms, aliases and countries, region browsing, optional offline country map. Countries suggest several languages; patient selects, no flag-as-language identity. Selecting language opens clinical category grid immediately. Active session remains in memory when navigating; explicit end confirmation clears it. No previously completed patient sessions. Never ask name, CPR, DOB, case number or consent checkbox as an entry gate.

Clinician UI and patient locale independent. All 45 target locales planned for both UI and clinical content, each independently reviewed/released. Clinical category overview: roomy two-column grid with icon and short name, use supplied 30 categories with concise labels and grouping. Subcategory menus: spacious flat list or simple cards, not dense dashboards; reduce nesting where possible. Questions selected individually in UI language; no obligatory next/previous sequences or progress bars. Search questions in UI language, support favorite question IDs. Same permanent ID can occur in multiple categories. Clinical groupings anatomical/symptom based, not diagnoses or differential diagnosis lists (past diagnoses may be asked as history). Heart contains chest pain, overlapping thorax and lungs where useful. No auto-path, no diagnosis-based scoring.

## Patient screen
Distinct large, centered question area. Show patient language only by default; tap question to toggle clinician translation (repeat tap restores). Patient answer labels, numeric units, control labels and headings localized in patient language. Large side-by-side Yes/No, equal size and prominence, smaller Don't know / Don't understand below. No “prefer not to answer” button; patient may decline without being recorded, back/skip leaves no answer. On single-tap answer return to question list; provide simple undo/correction; explicit confirmation for complex values. No initial selected values. No need for Next for yes/no. Do not auto-record on viewing. No symptom multi-select or “which symptoms” menu; ask nausea/dizziness etc separately. Single choice allowed where intrinsically needed (time interval); multi-mark body map is one question. Count e.g. vomiting uses large minus/value/plus or numeric keypad with clear confirm; null until chosen. Avoid excessive MCQs. Information/instruction screen: large patient text, simple localized close/back; no explanatory filler, no implied acknowledgment or consent. Optional display event explicitly marked shown, never answered/understood automatically.

Meal questions independent: Have you eaten breakfast today? Lunch today? Dinner today? Have you eaten within the last six hours? Each separate yes/no screen. Fever: Have you had a fever? Prefer this over exact temperature (temperature may remain optional secondary clinical item only if reviewed). Time since symptom onset fixed options: Within last hour; Within last six hours; Within last 24 hours; Several days ago; Several weeks ago. To avoid nested answers, proposed implementation uses mutually exclusive labels “Within the last hour”, “1–6 hours ago”, “6–24 hours ago”, “Several days ago”, “Several weeks ago”; maintain original requested intent and flag wording for maintainer review. Include don't know/don't understand; never infer exact times. For clinical situations requiring precise time (e.g. last known well), retain a separately selected specific date/time question if approved; do not equate coarse symptom onset with last known well. 
Body diagram: realistic neutral adult front and back, visible face/back landmarks, correct anatomical laterality, explicit translated front/back, multiple points or regions, separate pain localization and radiation screens, clear/reset and confirm. No diagnosis or sex inference. NRS 0–10 integer slider or accessible step buttons with localized anchors; initially no selection. User calls it VAS, technically NRS; label “Pain intensity”, not false VAS claim.

## Log and handoff
One canonical answer event per action. Log view: large ABCDE / SAMPLER / OPQRST / Other headings and clearly visible letters with expanded localized names, e.g. SAMPLER > A Allergies. Chronological within section; optional All chronological view. Literal UI-language question and literal selected answer, time; edit/delete with confirmation where relevant. No synthesized statements or objective ABCDE assessment. Multiple mappings may show same event under different groups, never duplicate storage or miscount. Repeated questions remain separate timestamped events unless editing existing answer; different symptoms must not be conflated. Empty sections show no entries, not “normal”. Copy literal grouped text with language and disclaimer; QR export/import of active log only. Explicit end clears memory and returns to picker. No source-person label, patient identifiers, freeform patient notes or history screen.
